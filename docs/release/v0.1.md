# Release checklist: v0.1, KK only

v0.1 builds Map Libraries from a KK install on Linux x64, Windows x64 and macOS arm64, in Blender 5.2 LTS and the latest release. There is no CI (ADR 0006), so every box below is ticked by hand, on a machine with a KK install, before the release is tagged. A copy of the game's folder from another machine is enough: the Extractor reads files only (ADR 0001).

Write who checked each box, on what (OS version, Blender build, RAM), and anything that was off.

## On the development machine (Linux x64)

- [ ] `../kkbp/importer/.venv/bin/python -I -m pytest tests` passes.
- [ ] `tools/golden.py` and `tools/build_golden.py` match their snapshots on `min` and `latest`.
- [ ] `tools/look.py` and `tools/look.py --camera game` pass or have accepted every view, on `min` and `latest`.
- [ ] `python3 tools/lock_deps.py` leaves `deps/lock.json` unchanged (or its diff is reviewed and committed).
- [ ] `python3 tools/package.py` makes three zips, each validated, each with every pinned wheel and no FMOD wheel.
- [ ] `python3 tools/product_check.py` passes on `min` and `latest`: the zip installs into a throwaway profile, no dependency problems, the Golden Maps build through the driver and match both snapshots, UnityPy never loads in Blender's process, and the Map Library is registered.
- [ ] A full KK Build (every Map) through the driver finishes, with the time, the disk and the peak memory of each step written down here, and every Map that wasn't built explained. The estimate in `jobs/driver.py` is updated if it was far off.
- [ ] In a Blender with a throwaway profile (`BLENDER_USER_RESOURCES`), by eye: the panel's tab, picking the game and output folders, listing the Maps, the estimate, starting a Build, Blender staying usable while it runs, the progress bar, Cancel, Resume, quitting Blender mid-Build (the Build stops; Resume afterwards carries on), the Build Report summary, Open Build Report, Add to Asset Libraries (asks first), and dragging a Prop, a Structure and a Map Variant into a new file.
- [ ] Changing the Camera Profile and building again rebuilds every Map file; building again without a change keeps them all.
- [ ] A folder that isn't a game install, and a KKS or SVS install, are each turned down with a message that says what to do.

## On Windows x64 (needs the user or another machine)

Install `kkbp_maps-0.1.0-windows_x64.zip` with Preferences > Get Extensions > Install from Disk, in a Blender 5.2 LTS and in the latest release, each with a fresh profile.

- [ ] The extension installs and its wheels with it; the panel shows no dependency problem.
- [ ] The Golden Maps (1f, ground, park) build. Their Build Report matches Linux's (the same Maps, Map Variants, Props, Structures, shader tiers and unknown words).
- [ ] No console window opens for a step while a Build runs.
- [ ] Blender stays usable during a Build; Cancel stops it within a few seconds; Resume carries on.
- [ ] Quitting Blender mid-Build stops the Build: no `python.exe` or `blender.exe` of the Build is left in Task Manager.
- [ ] The memory watchdog reads its counters: `build.log` shows no "can't read" notice, and each step's peak is above zero.
- [ ] A game folder and an output folder with spaces and non-ASCII characters in their paths (such as a Japanese user name) work.
- [ ] A deep output folder works: Windows' 260-character path limit is not hit by `Map Bundles\KK\map\scene\...` or `KK Maps\textures\...`. Note the deepest path written.
- [ ] Add to Asset Libraries adds `KK Maps`; the Asset Browser shows its catalogs, previews and tags; dragging assets in appends them.
- [ ] A full KK Build finishes; write down its time, disk and peak memory.

## On macOS arm64 (needs the user or another machine)

Install `kkbp_maps-0.1.0-macos_arm64.zip` the same way, in Blender 5.2 LTS and the latest release.

- [ ] The extension installs and its wheels with it, with no Gatekeeper prompt for the native wheels; the panel shows no dependency problem.
- [ ] The Golden Maps build, and their Build Report matches Linux's.
- [ ] Blender stays usable during a Build; Cancel and Resume work; quitting Blender stops the Build (no process of it left in Activity Monitor).
- [ ] The memory watchdog reads its counters (no "can't read" notice in `build.log`, peaks above zero).
- [ ] Paths with spaces and non-ASCII characters work, and a game folder on an external drive (case-insensitive APFS or exFAT) works.
- [ ] Add to Asset Libraries, the Asset Browser and dragging assets in work.
- [ ] A full KK Build finishes; write down its time, disk and peak memory.

## Releasing (the user)

- [ ] The version in `blender_manifest.toml` and `kkbp_maps/__init__.py` is the one being released, and the README's status says what v0.1 does.
- [ ] The three zips are attached to a GitHub release with a short note: KK only, Blender 5.2 or later, one zip per platform, no game content inside, the Bundle Folder's disk use, and where to report a Map that wasn't built.
- [ ] Optionally, the zips are submitted to extensions.blender.org (ADR 0029 makes that possible).

## Results so far

- 2026-11-25, Linux x64 (14 GB RAM, 19 GB swap), Blender 5.2.2 and 5.3.0: the tests, the Golden Map and build snapshots, `tools/package.py` (Linux 18.4 MB, Windows 11.8 MB, macOS 7.0 MB) and `tools/product_check.py` pass on both builds.
- 2026-11-25, Linux x64, Blender 5.2.2, the packaged extension in a throwaway profile: a Build of every KK Map (43, 1137 MB of Scene Bundles) took 19.3 min and built all 43: 123 Map Variants, 394 Props, 1021 Structures, 26 words the Name Tables don't know. Extraction took 11.6 min in all, the Map files 4.8 min, Props.blend and Structures.blend with their previews 2.7 min. Peaks: 0.86 GB for an extraction, 0.61 GB for a Map file, 1.87 GB for the asset files. Disk: 1.4 GB of Map Bundles and 0.7 GB of Map Library. (The first run, before ADR 0031, left out warehouse.)
- 2026-11-25, Linux x64, after ADR 0031: the look check on Blender 5.2.2 and 5.3.0 has no failing view and no regression from the look snapshot. Studio's camera: 24 of 35 views pass both comparisons and 11 are accepted. The story game's camera: 25 pass and 10 are accepted.
